# Research: adding Python source support

The conservative syntax-only release described here has since been implemented;
see [Python integration](tree-sitter-python.md) for the shipped contract.
The expanded facts and semantic options below remain follow-up proposals.

## Recommendation

Add **syntax-only `.py` extraction** through the existing vendored Tree-sitter/NIF pipeline first. Ship a small, explicit fact contract (definitions, syntactic calls, comments, source-written annotations) and distinguish it from resolved calls, imports, inferred types, and runtime behavior. Defer semantic analysis until a separate scope and provenance contract is agreed. This follows the repository's Ruby integration pattern and its split between TypeScript syntax and opt-in checker facts. [Local Ruby integration](tree-sitter-ruby.md) · [Local schema](prolog-schema.md)

## What exists today

- The directory walker accepts only `SCAN_EXTENSIONS`, which omits `.py`; `language_from_ext/1` has no Python mapping. The dispatcher `ts_extract:file/1` also lacks a `.py` branch. Explicit file paths bypass the extension filter, so adding only one of these changes is insufficient. [Scanner](../src/symbolic_parse.erl) · [Dispatcher](../src/ts_extract.erl)
- Each language has a vendored generated grammar under `c_src/grammars/`, built by `native/symbolic_ts/build.rs`, exposed through `ffi.rs`, `lib.rs`, and the Erlang NIF stub, then consumed by a language extractor. The Ruby extractor and tests are a compact integration example. The vendored core accepts Tree-sitter language ABI 13–15 (its current version is 15); grammar upgrades can change node shapes. [Build](../native/symbolic_ts/build.rs) · [FFI](../native/symbolic_ts/src/ffi.rs) · [Core API](../c_src/tree-sitter/include/tree_sitter/api.h) · [Ruby extractor](../src/ts_extract_ruby.erl) · [Tests](../test/ts_extract_ruby_tests.erl)
- The present cached scan reports 192 files, 81,823 facts and languages `bash, clojure, erlang, json, markdown, ruby, rust, toml, typescript`, not Python. This describes the configured scan paths, not all possible project files. [MCP parse/overview, 2026-12-10; repository cache]

## Primary-source findings

1. The upstream [`tree-sitter-python` grammar](https://github.com/tree-sitter/tree-sitter-python) is available under [MIT](https://github.com/tree-sitter/tree-sitter-python/blob/v0.25.0/LICENSE). At [release v0.25.0](https://github.com/tree-sitter/tree-sitter-python/releases/tag/v0.25.0), generated [`src/parser.c`](https://github.com/tree-sitter/tree-sitter-python/blob/v0.25.0/src/parser.c) declares `LANGUAGE_VERSION 15`; the grammar also has [`src/scanner.c`](https://github.com/tree-sitter/tree-sitter-python/blob/v0.25.0/src/scanner.c) and generated [`src/node-types.json`](https://github.com/tree-sitter/tree-sitter-python/blob/v0.25.0/src/node-types.json). The release archive has now been pinned by SHA-256, vendored and tested with the repository's NIF and Python fixtures. [Tree-sitter parser integration](https://tree-sitter.github.io/tree-sitter/using-parsers/1-getting-started.html) · [Local build](../native/symbolic_ts/build.rs)
2. The grammar exposes `function_definition` with `name`, `parameters`, `return_type`, `body`, plus `decorated_definition`, `class_definition`, `call` with `function` and `arguments`, `import_statement`, `import_from_statement`, and `comment`. Its parameters include positional-only `/`, keyword-only `*`, defaults, typed parameters and splats; call arguments include keyword arguments and splats. `named_child_count(parameters)` is therefore **not** Python callable arity, and call argument count is not enough to assert that a call resolves to a declaration. [Pinned grammar](https://github.com/tree-sitter/tree-sitter-python/blob/v0.25.0/grammar.js) · [Python `ast.arguments` and `ast.Call`](https://docs.python.org/3.13/library/ast.html#ast.arguments)
3. Python modules have executable top-level statements, nested definitions, classes, decorated methods, lambdas, and comprehension scopes. Python's own AST distinguishes `FunctionDef`, `AsyncFunctionDef`, `ClassDef`, `Lambda`, and `Call`; the `symtable` API describes identifier scopes, if later needed for binding work. A bare call `foo()` and attribute call `x.foo()` describe syntax, **not** a proved callee (descriptors, rebinding, inheritance, and callable instances matter). [Python AST](https://docs.python.org/3.13/library/ast.html#abstract-grammar) · [Symbol tables](https://docs.python.org/3.13/library/symtable.html) · [Callable and method model](https://docs.python.org/3.13/reference/datamodel.html#the-standard-type-hierarchy)
4. A `#` outside a literal is a comment; a docstring is a string expression in a module, class, or function body, not a `comment` node. Source encoding declarations can appear on the first or second line, and the default is UTF-8. The project currently reads raw file bytes into Tree-sitter; specify whether non-UTF-8 `.py` sources are decoded and re-encoded with location preservation, or reported as unsupported. Do not silently attribute wrong byte spans. [Python lexical rules](https://docs.python.org/3.13/reference/lexical_analysis.html#encoding-declarations) · [Python `ast.get_docstring`](https://docs.python.org/3.13/library/ast.html#ast.get_docstring) · [Local extractor input](../src/ts_extract_ruby.erl)
5. `import` statements are not a reliable complete dependency graph: Python imports also occur through `importlib`, and package resolution depends on finders, paths, and namespace packages. Record raw import syntax first; require a separately specified environment and resolution policy before claiming dependencies. [Python import system](https://docs.python.org/3.13/reference/import.html#the-import-system) · [Package relative imports](https://docs.python.org/3.13/reference/import.html#package-relative-imports)

## Implementation slices (1–2 shipped conservatively; 3–4 remain follow-up options)

1. **Grammar and routing:** vendor the pinned grammar/license; add it to `GRAMMARS`, FFI declaration, Rust NIF export and Erlang stub; add `.py` to scan extensions, extension-to-language reporting, dispatcher and invalid-extension help text. Include build, NIF load, configured-directory scan, explicit-file scan, and `.gitignore` tests. [Build](../native/symbolic_ts/build.rs) · [NIF](../native/symbolic_ts/src/lib.rs) · [Scanner](../src/symbolic_parse.erl)
2. **Bounded Python extractor:** new `ts_extract_python:file/1,text/2`; detect `function_definition` inside `decorated_definition`, including `async def`, nested functions and class methods without double-counting. Emit `defines/5`, `comment/3` and a conservative `calls/5` only where caller identity is unambiguous. Keep params as source text and document that any `Arity` is a **syntactic count of declared parameters**, not minimum/maximum accepted call arguments or bound-method arity. For `*args`/`**kwargs` and keyword calls, either preserve a distinct syntax-only fact with span/identity or explicitly omit unrepresentable calls; do not force them into a misleading exact-arity `local/2` or `member/3` relation. [Pinned grammar](https://github.com/tree-sitter/tree-sitter-python/blob/v0.25.0/grammar.js) · [Local fact schema](prolog-schema.md) · [Python call AST](https://docs.python.org/3.13/library/ast.html#ast.Call)
3. **Additional syntax and documentation:** decide whether to emit separate `python_*` facts for class/nested definition identity, raw imports and source-written annotation text/spans, so duplicate method names and overload-like shapes remain distinguishable. If supporting docstrings, extract only literal first-body statements and specify whether these become `doc/5` or a new fact; keep `#` comments separate. Update `docs/prolog-schema.md` and standalone Python integration notes. [Python AST](https://docs.python.org/3.13/library/ast.html#ast.get_docstring) · [Local schema](prolog-schema.md)
4. **Verification:** fixture matrix for top-level/nested functions, duplicate names across classes, decorators (`@staticmethod`/`@classmethod`), async, positional-only/keyword-only/defaults, `*args`/`**kwargs`, chained/keyword calls, relative imports, docstrings vs `#`, multiline/f-string calls, syntax errors, non-ASCII identifiers and non-UTF-8 declarations. Compare emitted facts with the documented contract; test cache refresh after a Python file changes. Benchmark file count, fact count, time and peak RSS on a representative Python project. [Python syntax and encoding](https://docs.python.org/3.13/reference/lexical_analysis.html) · [Local scan/cache](../src/symbolic_parse.erl)

## Open scope decisions

- Is the target simply source search / definitions / comments, or credible Python call and import graphs? The current `calls/5` convention is a syntactic call-site shape, not a resolved edge; existing derived `callers`/`truly_uncalled` queries may overstate Python results if the difference is not documented. [Local schema](prolog-schema.md) · [Python method binding](https://docs.python.org/3.13/reference/datamodel.html#instance-methods)
- Should Python annotation support mean **written annotations** only, or optional inferred/project types? These are different deliverables, as with TypeScript's `ts_syntax_type/8` vs checker facts. A Python interpreter's AST and `symtable` do not by themselves provide project-wide inferred types. [Python AST](https://docs.python.org/3.13/library/ast.html) · [Python symbol tables](https://docs.python.org/3.13/library/symtable.html) · [Local schema](prolog-schema.md)
- Which Python versions/encodings should be supported? Grammar compatibility must be established with fixtures rather than inferred from a matching Tree-sitter ABI. [Pinned grammar](https://github.com/tree-sitter/tree-sitter-python/blob/v0.25.0/grammar.js) · [Python encoding declarations](https://docs.python.org/3.13/reference/lexical_analysis.html#encoding-declarations)
